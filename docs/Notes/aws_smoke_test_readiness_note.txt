AWS Smoke Test Readiness Note

Purpose

Record the current readiness assessment and first-run plan for an AWS GPU smoke
test, so setup can resume later without re-deriving the operational steps.

Readiness assessment

The repository is ready for a first AWS GPU smoke test once the external AWS
account, EC2 access, GPU quota, and dataset placement are handled.

The code path is ready enough because:

- `model/setup.zsh` auto-detects CUDA and supports an explicit `PYTHON_BIN`.
- The setup script writes logs/checkpoints/final weights to a unique run
  directory by default, so smoke and retry outputs are not overwritten.
- `VES_SEED` controls Python, NumPy, PyTorch, subset, split, and sampler
  randomness for comparable provider runs.
- Smoke mode can force a tiny run with `VES_SMOKE_TEST=1`, `VES_MAX_SIZE=64`,
  `VES_BATCH_SIZE=2`, and `VES_SIZE_PROFILE=64`.
- The repository includes `data/alpub_v2_manifest.json`.
- The local tracker records that the CPU smoke test passed.

Operational caveats

- Push the latest branch before launching the EC2 run. At the time this note was
  written, `uncial-pilot-prep` was ahead of `origin/uncial-pilot-prep` by one
  commit.
- Copy or download the extracted `ALPUB_v2/images/...` tree onto the EC2
  machine. The manifest references local image paths, so the training dataset is
  not usable unless those files exist under the repository root.
- Use an AWS Deep Learning AMI for PyTorch rather than hand-installing CUDA.
  The DLAMI path avoids spending the smoke test debugging NVIDIA driver, CUDA,
  and PyTorch build mismatches.
- Install `requirements-dlami.txt` on a PyTorch DLAMI rather than
  `requirements.txt`; this avoids replacing the AMI's GPU-enabled PyTorch
  package with a different pip build.
- Prefer a single-GPU L4/A10-class instance for the first run. A G6 instance
  with an NVIDIA L4 GPU is a reasonable AWS starting point if quota and regional
  availability permit it.
- AWS credentials do not need to be stored in a repository configuration file
  for a manual EC2 smoke test unless the run is automated through AWS CLI or S3.
  The manual path needs account access, EC2 launch permissions, SSH or SSM
  access, enough storage, and the dataset.

Initial GPU diagnostic

Run this on the EC2 host before training:

```bash
python - <<'PY'
import sys
import torch

print("python:", sys.executable)
print("torch:", torch.__version__)
print("cuda build:", torch.version.cuda)
print("cuda available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print("gpu:", torch.cuda.get_device_name(0))
PY
```

First smoke command

Assuming the AWS PyTorch DLAMI Python is available at `/opt/pytorch/bin/python`:

```bash
cd model

PYTHON_BIN=/opt/pytorch/bin/python \
VES_SMOKE_TEST=1 \
VES_FORCE_CPU=0 \
VES_MAX_SIZE=64 \
VES_BATCH_SIZE=2 \
VES_NUM_EPOCHS=1 \
VES_SIZE_PROFILE=64 \
VES_SEED=42 \
./setup.zsh
```

Use `VES_DEBUG_CUDA=1` only if the first run fails with a CUDA error and a
synchronous stack trace is needed. Smoke runs default to a 1200-second hard
timeout; non-smoke validation runs default to no hard timeout unless
`VES_HARD_TIMEOUT` is set explicitly.
