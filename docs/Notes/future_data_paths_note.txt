Future Data Paths and Self-Supervised Pretraining Note

Purpose

Record possible data directions beyond the current ALPUB_v2 supervised crop
regime, with special attention to self-supervised pretraining on unlabeled
manuscript or papyrus imagery.

Current position

The current ALPUB_v2 training path is still producing useful learning signal on
larger bounded subsets. New data is therefore not an immediate prerequisite for
continued progress. The near-term priority remains:

- finish bounded GPU validation
- add or verify checkpoint resume
- inspect qualitative outputs
- establish stronger held-out and transfer-oriented evaluation

New data becomes the main lever once validation loss plateaus, qualitative
outputs stop improving, or the model fails to transfer beyond curated uncial
crops.

Candidate future data paths

1. More labeled uncial or majuscule character crops

This would be the cleanest extension because it matches the current task
directly. The limitation is availability: there may not be another large,
well-labeled uncial crop corpus comparable to ALPUB_v2.

Use case:

- continue the current supervised crop task
- improve class coverage and document diversity
- test whether learned forms generalize across scribal hands and collections

2. Full manuscript or papyrus images with known transcriptions

This may be more realistic than finding another labeled character-crop corpus.
The supervision is weaker because the image usually does not come with exact
character boxes or masks. It would require an alignment or preprocessing
pipeline.

Possible approaches:

- line segmentation followed by text-line recognition
- weak alignment between image regions and known transcription strings
- automatic or semi-automatic character proposal generation
- human review of uncertain alignments
- training on page or line context rather than isolated crops

This path may move the project closer to real reading, but it is also a larger
engineering and evaluation task.

3. Unlabeled manuscript or papyrus imagery

Unlabeled images are valuable if used for representation learning rather than
direct supervised performance. The model can learn visual regularities from
large amounts of manuscript texture, stroke structure, background variation,
damage, and layout without requiring labels for every crop.

This is the most interesting path for self-supervised pretraining.

4. Synthetic augmentation and degradation

Synthetic methods remain useful as augmentation, especially for stress-testing
transfer:

- contrast shifts
- blur
- noise
- rotation and mild affine distortion
- stroke thinning or thickening
- background corruption
- partial occlusion

The risk is that the model may learn artificial corruption artifacts rather than
real manuscript structure. Synthetic data should therefore be treated as a
controlled perturbation, not as the source of truth.

5. Related scripts or related visual domains

Other Greek majuscule, early Byzantine, papyrus, or manuscript materials may
provide useful visual pretraining data even when they are not exact uncial
matches. This should be tested empirically because a visually distant source may
teach features that do not transfer.

Self-supervised pretraining

Self-supervised pretraining is appealing because it separates two questions:

- Can the model learn useful visual structure from unlabeled manuscript images?
- Does that learned structure improve the downstream supervised or transfer
  task?

In this setup, unlabeled data is used for training an encoder or representation.
Labels are still needed later for evaluation. The proof is not that the model
trained without labels at all; the proof is that unlabeled pretraining improves
performance when tested on a meaningful held-out or transfer task.

Possible self-supervised objectives

1. Masked image modeling

Hide patches of a manuscript crop or tile and train the model to reconstruct the
missing visual content. This is conceptually close to the present reconstruction
orientation and may be a natural fit for damaged text.

Potential benefit:

- learns stroke continuity
- learns local manuscript texture
- may help infer missing or faint structure

Risk:

- may overemphasize background reconstruction rather than letter structure

2. Contrastive learning

Train the model so that two augmented views of the same image region have
similar representations, while unrelated regions are farther apart.

Potential benefit:

- learns robust visual features without labels
- may improve resilience to noise, contrast changes, and damage

Risk:

- augmentations must be chosen carefully; unrealistic transformations can teach
  the wrong invariances

3. Denoising or degradation recovery

Corrupt real manuscript crops or tiles and train the model to recover the
cleaner original. This overlaps with augmentation but uses the real image as the
anchor.

Potential benefit:

- directly targets robustness to degraded imagery
- may help bridge from curated crops to noisy scroll-like data

Risk:

- the "clean" target is still only the observed image, not necessarily the true
  underlying ink signal

4. Patch ordering or local-context prediction

Train the model to predict whether nearby patches belong together, or to infer
relative spatial relationships among patches.

Potential benefit:

- learns layout and stroke continuity
- may be useful for full-page or tiled scroll imagery

Risk:

- may learn page texture or layout shortcuts instead of text features

How to test whether self-supervised pretraining helps

The methodology should compare at least two models under matched downstream
conditions:

1. Baseline

- random initialization
- supervised training on ALPUB_v2 or another labeled set
- fixed train/validation split
- fixed seed, batch size, learning rate, and epoch count

2. Self-supervised pretrained model

- pretrain on unlabeled manuscript or papyrus images
- initialize the supervised model from the pretrained encoder
- run the same downstream training configuration as the baseline

Evaluation questions:

- Does the pretrained model reach lower validation loss?
- Does it reach the same validation loss in fewer epochs?
- Does it perform better with fewer labels?
- Does it transfer better to held-out documents or harder image conditions?
- Do qualitative outputs look less artifact-driven?
- Does expert inspection find more plausible letter structure?

The strongest proof would be a low-label or cross-domain test:

- Train both models with only a small labeled subset.
- Evaluate on held-out documents or harder transfer imagery.
- If the self-supervised model performs better, then unlabeled data is adding
  real value rather than merely reproducing the supervised result.

Possible staged plan

Stage 1: continue supervised GPU validation

- use the current ALPUB_v2 setup
- add checkpoint resume
- run larger subsets and inspect outputs
- establish the current supervised ceiling

Stage 2: collect unlabeled candidate imagery

- prioritize uncial, majuscule, papyrus, and manuscript images close to the
  target domain
- include full-page or full-fragment images where available
- preserve source metadata and licensing information

Stage 3: pretrain an encoder

- start with masked image modeling or denoising because they match the current
  reconstruction logic
- keep the pretraining objective separate from final evaluation
- save pretrained encoder checkpoints with reproducible metadata

Stage 4: supervised fine-tuning comparison

- fine-tune from pretrained weights on ALPUB_v2
- compare against random initialization under identical settings
- test low-label performance and held-out document transfer

Stage 5: scroll-like transfer test

- run tiled inference on novel grayscale material
- judge outputs by stability, plausibility, and expert inspection, not by loss
  alone

Important methodological point

Unlabeled data can teach the model useful representations, but it cannot by
itself prove that the model reads text. The decisive test remains downstream
performance: whether pretraining on unlabeled imagery improves held-out,
low-label, or transfer behavior compared with a supervised baseline trained from
scratch.
