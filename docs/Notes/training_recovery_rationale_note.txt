Training Recovery Rationale

Date: 2026-06-09

Why the current branch now needs more recovery machinery than Hugo's original
training setup:

- Hugo's source dataset was about 14 MB, organized as 96 folders with roughly
  450 files each, or about 43,200 files total.
- The current ALPUB_v2 manifest contains 205,797 loadable records.
- The current branch also applies degradation on the fly while training, so the
  data path does more work than simply reading fixed pregenerated pairs.
- The current AWS run is on EC2, where SSH sessions and the guest instance have
  already become unhealthy during long GPU jobs.

For Hugo's original scale, epoch-boundary checkpointing was a reasonable
engineering choice. If one epoch was short, losing part of an epoch was not a
major operational risk. Adding intra-epoch checkpoints, resumable sampler state,
and cloud-job recovery would likely have been unnecessary complexity.

For the current ALPUB_v2 run, the assumptions changed. A full epoch can run long
enough that losing partial progress is expensive, and the cloud instance has
shown enough instability that recovery is now part of the training system, not a
nice-to-have convenience.

Changes made for the current branch:

- Added intra-epoch recovery checkpoints that store model, optimizer, scheduler,
  scaler, RNG state, epoch, batch, global step, and running loss totals.
- Added `VES_RESUME_TRAINING_STATE` for full recovery checkpoint resume, while
  preserving the older `VES_RESUME_FROM` weight-only resume path.
- Made recovery loading tolerate lazy model parameters such as attention
  `global_bias` entries that exist in a checkpoint after a forward pass but are
  absent in a freshly constructed model.
- Restored RNG state through CPU tensors so checkpoints saved on GPU can resume
  without `torch.set_rng_state` type errors.
- Changed resume behavior to precompute the deterministic epoch training order
  and slice from `next_batch * batch_size`, instead of rebuilding the loader and
  iterating through thousands of skipped batches.

The model premise can still be sound while the training mechanics evolve. The
main difference is scale: the inherited method crossed a threshold where
production-style training operations are now required.
